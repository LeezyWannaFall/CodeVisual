# Архитектура CodeVisual

## Поток данных

```text
CLI → Discover / Load → индекс символов → анализаторы
    → Merge → Snapshot → локальный HTTP API → React-интерфейс
```

Анализ выполняется перед запуском HTTP-сервера. Сервер использует готовый snapshot;
исходники запрашиваются отдельно с проверкой хеша. Изменение исходника требует
повторного анализа. Автоматическое обновление snapshot пока не реализовано.

## Модель и API

Анализаторы возвращают `graph.AnalysisResult`: узлы, связи, файлы и диагностики.
`graph.NewSnapshot` проверяет целостность модели и создаёт индексы. Предупреждения
и ошибки переводят анализ в статус `partial`.

API расположен под `/api/v1`: project, tree, graph, search, nodes, files,
diagnostics. `Snapshot.View` строит представления пакетов, каталогов, символов,
HTTP и БД; `Snapshot.Flow` обходит связи вызовов. Представления ограничены
`graph.MaxViewNodes` (сейчас 200). Не путай страницу представления с полным набором
результатов анализа.

SQL-представление описывает найденные DDL-объявления, а не итоговое состояние БД
после применения всех миграций. Request Flow описывает потенциальные вызовы,
а не порядок выполнения запроса.

HTTP-анализатор сохраняет регистрации по экземплярам роутеров, затем
разворачивает Mount с префиксами и унаследованными middleware. Возвращённый
из builder роутер сохраняет идентичность при добавлении маршрутов.

## Сборка интерфейса

Vite собирает фронтенд в `internal/server/webdist`; Go включает эти файлы через
`embed`. Исходники интерфейса и встроенная сборка хранятся в репозитории.
После изменений в `web` используй `make frontend` и проверяй полученный diff.

## Проверки

- Go-тесты рядом с пакетами проверяют анализаторы, модель, загрузку, CLI и API.
- Vitest проверяет компоненты, графовую логику и контракт API.
- Playwright проверяет пользовательские сценарии на тестовых проектах.
- Дополнительные e2e-сценарии для внешних проектов включаются переменными
  окружения; детали находятся в `web/playwright.config.ts`.

## Автоматизация проверок и выпуска

- `.github/workflows/ci.yml` — Go-проверки на трёх ОС, фронтенд, e2e и кросс-сборка.
- `.github/workflows/release.yml` — проверки, архивы и черновик релиза по тегу.
- `scripts/check_webdist.py` — проверка отличий встроенной сборки от коммита,
  включая новые файлы, которые ещё не отслеживаются Git.
- `scripts/release.py` — шесть архивов и SHA256SUMS, без сторонних Python-библиотек.

`internal/cli.Version` задаётся при сборке релиза. `--version` работает без
установленного Go; перед анализом проверяется доступная в PATH версия Go.
