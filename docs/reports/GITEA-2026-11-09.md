интерфейса и терминала, полный текст 49 диагностик, чтение реализации CodeVisual.
Повторный запуск анализа агентом в рамках отчёта не выполнялся.

## Статус

Первичная ручная проверка большого Go-проекта завершена. Это исследовательский
прогон, а не полная приёмка, доказательство точности всех связей или воспроизводимый
бенчмарк. Этап измерений производительности roadmap целиком не закрыт.

## Оставшиеся диагностики

- 4 docker_copy_flags: COPY --exclude/--parents не разворачивается.
- 2 docker_variables: переменные WORKDIR не подставляются.
- 1 package_load: build constraints исключают Go-файлы каталога build.
- 42 unresolved_package: повторяющиеся сообщения об импортах gitea.dev/actionslib
  и gitea.dev/sdk. Это число сообщений, а не число уникальных пакетов.

Ошибка build constraints может соответствовать допустимому набору build tags;
нужно сверить назначение файлов. Docker-предупреждения отражают ограничения
статического анализа, а не необходимость запуска Docker.

В golang/analyzer.go внутренний импорт сейчас определяется совпадением modulePath
или его строкового префикса. Если modulePath равен gitea.dev, отдельные модули
с путями gitea.dev/actionslib и gitea.dev/sdk могут ошибочно считаться отсутствующими
внутренними пакетами. Это конкретная гипотеза дефекта, требующая минимальной
фикстуры с корневым модулем и отдельным модулем с общим префиксом; скачивание
зависимостей само по себе не обосновывает полноту анализа.

## Приоритеты исправлений

1. P1: воспроизвести и исправить классификацию импортов отдельных модулей с общим
   префиксом, используя сведения о модулях и границах корня. Добавить регрессию.
2. P2: объединять повторные диагностики по причине/объекту, показывать число мест
   и доступ к ним; отделять ограничения от ошибок загрузки. Предупреждать
   о несовпадении версии Go бинарника и загрузчика один раз.
3. P2: улучшить навигацию больших графов: обзор групп, фокус на окружении узла,
   читаемый начальный масштаб и явное объяснение скрытых связей. Не повышать
   лимит узлов без измерений.
4. P2: поддержать статически разрешимые ARG/ENV в WORKDIR и COPY --exclude/--parents
   с минимальными фикстурами; неизвестные значения по-прежнему диагностировать,
   не исполнять RUN и не читать вне build context.
5. P3: самостоятельный Dockerfile подписывать как конфигурацию сборки, а не SERVICE;
   проверить перенос длинных образов и высоту карточек.
6. P3: убрать пустоты сетки обзора объявлений при разной длине документации:
   сворачиваемое описание или перенос в инспектор, с проверкой доступности текста.

## Что нужно для следующей проверки

Зафиксировать SHA Gitea и CodeVisual, версию Go сборки/анализа, ОС/архитектуру,
build tags, CPU/RAM и расположение кешей без персональных путей. Выполнить несколько
сопоставимых холодных и повторных запусков, измерить peak RSS и задержки поиска,
раскладки и переходов. Сверить выборку объявлений/импортов/копирований с исходниками.
Python, Compose и нативные платформы проверять отдельными наборами: этот прогон
Gitea их не покрывает. Реализация приоритетов описана ниже; повторный прогон Gitea после исправлений ещё не выполнен.

## Реализация по результатам отчёта

- P1: независимые required-модули с общим префиксом исключены из классификации
  внутренних импортов. Локальный replace воспроизводит ошибку без сети.
- P2 диагностики: интерфейс группирует одинаковые причины и раскрывает
  сохранённые occurrences; доступен переход к узлу/совпадающему исходнику.
  Ошибки загрузки отделены от ограничений. Версионное предупреждение Go
  формируется один раз на модуль вместо повторов source-processing warning.
- P2 графы: начальный масштаб для >30 узлов не ниже 0.45; доступны Fit view,
  фокус выбранного узла и переход к существующей группировке каталогов.
  Лимит 200 узлов и пагинация не изменены.
- P2 Docker: простые известные ARG/ENV, области видимости стадий, WORKDIR,
  локальные COPY --exclude и --parents (/./) покрыты тестами.
  Отображение --parents строится для известных исходников кода; неизвестная
  файловая система другой стадии остаётся диагностируемой границей.
  Значения хоста и RUN не исполняются; неизвестные подстановки не дают связей.
- P3: Dockerfile подписывается BUILD CONFIG; образы переносятся по ширине.
  Описания удалены из сетки карточек и сохранены в инспекторе.

Это реализация улучшений по первичному прогону, а не подтверждение устранения
всех 49 диагностик Gitea. Новое число диагностик и производительность нужно
измерить на том же SHA и сопоставимых условиях.
